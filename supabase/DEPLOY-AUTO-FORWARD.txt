نشر التمرير التلقائي على السيرفر (Cron — بدون متصفح)
═══════════════════════════════════════════════════════════════════════════

─── 1) نشر الدوال ───

الطريقة أ — GitHub Actions:
  Actions → Deploy push functions → Run workflow
  (يشمل violation-auto-forward + violation-push)

الطريقة ب — سطر أوامر:
  set SUPABASE_ACCESS_TOKEN=...
  npx supabase@2.30.4 functions deploy violation-auto-forward --no-verify-jwt --project-ref rizoafuxmqsddjfhbsmf --use-api
  npx supabase@2.30.4 functions deploy violation-push --no-verify-jwt --project-ref rizoafuxmqsddjfhbsmf --use-api

─── 2) سر الجدولة ───
Supabase Dashboard → Edge Functions → Secrets:
  AUTO_FORWARD_CRON_SECRET = نص عشوائي طويل (مثلاً 32+ حرف)

─── 3) تفعيل Cron (كل دقيقة) ───
افتح supabase/violation-auto-forward-cron.sql
استبدل YOUR_CRON_SECRET_HERE بنفس السر من الخطوة 2
شغّل الملف في SQL Editor

─── 4) تحقق ───
GET (متصفح):
  https://rizoafuxmqsddjfhbsmf.supabase.co/functions/v1/violation-auto-forward
  يجب: "service":"violation-auto-forward","version":"2026-06-v1"

POST (اختبار يدوي — PowerShell):
  $secret = "YOUR_CRON_SECRET"
  Invoke-RestMethod -Method POST `
    -Uri "https://rizoafuxmqsddjfhbsmf.supabase.co/functions/v1/violation-auto-forward" `
    -Headers @{ "x-cron-secret" = $secret; "Content-Type" = "application/json" } `
    -Body "{}"

violation-push يجب أن يظهر:
  "version":"2026-06-auto-forward-cron"

─── ملاحظات ───
• التمرير يعمل كل دقيقة (أقصى تأخير ~60 ثانية بعد انتهاء المهلة).
• المتصفح يبقى نسخة احتياطية فورية عند 00:00.
• سجلات التمرير تُكتب باسم «النظام» مثل الواجهة.
